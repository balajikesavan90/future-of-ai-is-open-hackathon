# Implementation Gap Audit

This audit compares current documentation claims with the implementation after second-pass cleanup.

| Claim | Evidence | Gap | Severity | Recommendation |
| --- | --- | --- | --- | --- |
| Inactive image-generation code was removed from active source. | `src/arctic_analytics/llm/openai_responses.py` no longer contains image-generation response branches or image-generation parameters. `docs/archive/REMOVED_FEATURES.md` records the removal. | Active plot generation still uses base64 PNG data URLs for matplotlib figures, which is separate from removed image-generation API support. | Low | Keep docs precise: "plot generation" is active; "image generation" is not. |
| Embeddings are not part of the active workflow. | No active embedding helper remains in `src/arctic_analytics/llm/openai_responses.py`. | `openai` dependency remains active for Responses API; no retrieval module exists. | Low | Reintroduce embeddings only in a documented retrieval/context module with tests. |
| Arctic Analytics is an experimental framework. | Package is installable, core/llm/streamlit modules exist, and README states framework positioning. | The current workflow is still Streamlit-centered and many core operations depend on `st.session_state`. | Medium | Keep "experimental" prominent and document framework debt. Avoid implying a stable library API. |
| Metadata is injected before inference. | `src/arctic_analytics/core/system_messages.py` injects dataset description, data dictionary, shape, summary stats, missing values, and row samples. | Context bundle is a prompt string, not a schema-backed, hashable artifact. | Medium | Add context bundle export later; do not claim replayable context yet. |
| Execution is constrained. | `src/arctic_analytics/core/security.py` validates AST, checks imports/functions/attributes, uses restricted globals, and times execution. | Constraints remain Python-level and thread-based; no OS/container isolation or resource quotas. | High | Keep all docs explicit that this is not sandboxing or a security boundary. |
| Unsafe imports and common escape paths are blocked. | `tests/test_security.py` now covers alias imports, forbidden builtins, attribute escapes, network imports, filesystem attempts, timeout behavior, and oversized outputs. | Tests increase confidence but are not a complete adversarial evaluation. | Medium | Continue adding focused regression tests when bypasses are found. |
| Trace export is available. | `src/arctic_analytics/streamlit/helpers.py` builds traces; `schemas/analysis_trace.schema.json` validates structure; `tests/test_trace_export.py` validates generated and sample traces. | Schema validation is structural only. There is no deterministic replay or semantic correctness check. | Medium | Keep "snapshot" wording and avoid "audit log" claims. |
| Examples support the workflow. | `examples/sample_dataset.csv`, `sample_metadata.json`, and `sample_trace_export.json` are documented and schema-tested. | Sample trace depends on an external model call and cannot be deterministically reproduced. | Medium | Keep examples labeled illustrative/external dependency/experimental. |
| Citation metadata is present. | `CITATION.cff`, `.zenodo.json`, README citation section, package version, and DOI references align on version `0.1.0` and DOI `10.5281/zenodo.18514535`. | Release process is manual. | Low | Use `docs/release_checklist.md` before release or archive. |
| Governance is not claimed. | README, security docs, threat model, and reproducibility docs reject governance guarantees and audit-grade provenance. | The UI does not include approval gates or durable review records. | Low | Keep governance as an explicit non-goal until implemented. |
