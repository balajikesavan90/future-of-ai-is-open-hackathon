# Research Questions

Arctic Analytics is a practical experiment in metadata-aware and inspectable AI-assisted analysis over structured data. The project should use implementation work to explore the following questions.

## Metadata And Context

- Does explicit metadata improve analysis quality compared with raw column names alone?
- Which metadata has the highest impact: dataset descriptions, column descriptions, data types, primary keys, summary statistics, missing values, or row samples?
- How much business context should be injected before the model starts analysis?
- What context should be written by users, inferred from data, or generated by tooling?
- How should context be represented so it can be reviewed, exported, and eventually replayed?

## Transparency And Trust

- Does showing generated code improve user trust?
- Does showing tool calls and tool responses improve user understanding?
- Which intermediate steps are useful, and which create noise?
- Should reasoning summaries, code, and outputs be displayed together or separately?
- What is the smallest useful trace for reviewing an AI-assisted analysis?

## Constrained Execution

- Which Python restrictions reduce meaningful risk without blocking common pandas analysis?
- How should the project distinguish Python-level validation from true sandboxing?
- What output constraints help keep model/tool loops useful?
- When should generated code be rejected before execution?
- What execution metadata should be captured for future replay?

## Human Review

- Where should the user be asked to review context before inference?
- Where should the user be asked to review generated code before trusting outputs?
- How should the interface communicate uncertainty and limitations without overwhelming the workflow?
- What should be exportable for peer review or debugging?

## Future Infrastructure

- What should a context bundle contain?
- Which hashes are useful: dataset profile hash, data dictionary hash, prompt hash, code hash, output hash?
- What would make a run replayable?
- What provenance is needed for uploaded datasets and edited metadata?
- When is isolated execution necessary, and what isolation boundary is sufficient?

## Current Non-Goals

- Arctic Analytics is not an enterprise governance platform.
- Arctic Analytics does not provide role-based governance.
- Arctic Analytics does not provide durable audit logs.
- Arctic Analytics does not provide replayable traces today.
- Arctic Analytics does not provide OS-level or container sandboxing today.
- Arctic Analytics does not claim a novel agent architecture.
